**Route:** technology-shock discovery and structural forecast  
**Base-case evidence cutoff:** 2026-10-29  
**Public capability-discovery update:** 2026-11-05  
**Event anchor:** TypeSafe AI's JEV interfaces; the research object is the broader functional class  
**Purpose:** show how to avoid turning a product launch into an industry winner

## Review card

**Memory sentence:** Cheap typed semantic decisions may move repetitive classification, routing, and guardrail work out of general-purpose generation, but the durable constraint may migrate to state preparation, question definition, calibration, exception handling, and acceptance rights.

```text
T = bounded semantic decision model class

dQ = evaluate a finite choice, score, or yes/no probability from text or
     structured state and return a typed result directly consumable by software

H = the user must define the question and answer space, select relevant state,
    keep deterministic relations in code, calibrate thresholds, and own errors

t = 2026-10-29
```

The class includes JEV-like typed decision models and adjacent lightweight routers, safety classifiers, and rerankers when they replace the same function. It excludes open writing, candidate invention, complex planning, exact arithmetic, and final legal or human authorization.

## Capability shock

| Primitive | What changes | Evidence ceiling |
|---|---|---|
| Typed choice/score/probability | A model result can enter a software branch without open-text parsing | Interface fact |
| Shared state, many atomic questions | Repetitive judgments can be decomposed and evaluated in parallel | Product-design fact |
| Lower unit cost and latency | More workflow locations may become economical | Vendor pricing/measurement; production TCO unknown |
| Confidence gating | Low-risk cases may automate while uncertain cases escalate | Mechanism; domain calibration must be tested |
| No open generation | The class complements rather than replaces generator/planner models | Explicit functional boundary |

### Before and conditional after

```text
Before:
business state
-> general LLM understands, judges, and emits structured text
-> parser / retry / repair
-> action or human review

Conditional after:
business state preparation
-> deterministic filtering and calculation
-> bounded semantic decision model
-> confidence gate
   -> automatic low-risk action
   -> generator/planner for open tasks
   -> human handling for high-risk or uncertain cases
-> outcome labels update questions and thresholds
```

## Four-direction event check

| Direction | Candidate effect |
|---|---|
| Substitution/relaxation | Reduces general-LLM token, latency, parsing, and some manual first-pass work for bounded decisions. |
| Complement activation | Makes state engineering, evaluation, threshold calibration, observability, and exception operations more valuable. |
| Interface convergence | A shared typed decision contract could let workflows switch among hosted, open, or cloud-integrated backends. |
| Demand expansion/pruning | More micro-decisions may be embedded in software; open-ended or high-liability uses remain outside the class. |

## Open-world impact discovery

The transferable primitive is not simply “cheap classification.” It is a lower-cost translation from ambiguous but prepared state into a typed branch that software can execute, reject, route, rank, or escalate. If the function qualifies, software can afford more semantic decisions per object and before more digital actions.

This discovery surface is deliberately broader than a beneficiary list. Each row separates current transfer evidence from the additional gate that a bounded industry audit must test.

### Ranked public shortlist

1. **Agent pre-action policy gates:** widest digital action surface, but the likely Gate is the platform that owns identity, permissions, policies and incident feedback—not automatically the model provider.
2. **Real-time fraud, onboarding and KYB:** strongest newly anchored industry candidate because judgment latency can enter a live customer path; final blocking, appeals and regulatory responsibility remain outside the model.
3. **High-volume recruitment and marketplace matching:** production-adjacent evidence supports cost and decision-density changes; fairness, employer acceptance and feedback bias require a separate audit.

The next search round should freeze `Y/Q/Omega/t` separately for these candidates. Their acceptance thresholds, rights and parent learning loops cannot be collapsed into one “JEV industry.”

## Bottleneck judgment

**Observed now:** a recognizable capability class and multiple adjacent implementations exist. The technical function is not confined to one vendor.

**Conditional structural transition:** if workflows move a material share of bounded judgments out of general generation while meeting quality and liability thresholds, the old general-LLM middle layer widens and the cut migrates toward problem definition, relevant state, domain labels, calibration, acceptance, and exception handling.

**Not established:** cross-industry production task share, stable calibration, long-term unit economics, or durable rent for TypeSafe AI or any single decision-model vendor.

### Who may gain control

| Actor | Possible gain | Why it is conditional |
|---|---|---|
| Vertical SaaS / enterprise workflow owner | More control over definitions, state, permissions, labels, and final acceptance | Requires deployment rights and reusable outcome feedback |
| Agent runtime / model gateway | Routing and evaluation become a control plane | Backends may remain substitutable or be absorbed by cloud/model vendors |
| Specialized model provider | Revenue from cheap, high-volume decisions | Low switching cost and open alternatives may cap capture |
| BPO / human review | Work shifts toward uncertain, high-loss, and accountable exceptions | Total employment depends on volume rebound and exception rate |

## Strongest objections

1. Small general-purpose models, structured output, rules, or conventional classifiers may be good enough and erase the separate category.
2. Decomposing work into many atomic questions may increase maintenance and latency rather than reduce them.
3. Production labels may be too sparse or delayed to calibrate confidence reliably.
4. Cloud and frontier-model vendors may absorb the interface, so the structure changes without creating an independent supplier waist.

## Registered observations

| Hypothesis | Supporting observation | Falsifier |
|---|---|---|
| Generator/planner and decision/judge roles separate | Independent runtimes expose decision-specific routing and usage | Most production systems continue to use one general model for all semantic steps |
| Effective supplier width rises | One workflow switches among hosted, open, and cloud decision backends without lowering acceptance quality | Domain performance or maintenance forces work back to one general model or one proprietary backend |
| Decision volume rebounds | Per-decision cost falls while atomic decisions and automated throughput rise | Decomposition raises total cost/latency and use remains sparse |
| Constraint migrates to definition and validation | Jobs, incidents, and tools concentrate on ontology, labels, thresholds, drift, and exception queues | The class deploys stably without domain labels, calibration, or exception operations |
| Category impact exceeds single-vendor rent | More implementations and lower prices coexist with growing decision-task share | One provider maintains durable performance and switching advantages across domains |

## Why this example belongs

It demonstrates a discovery problem: the analyst must first define a functional class, search non-obvious adjacent tasks, and then freeze separate industry cases. Capability evidence supports candidate mechanisms, not completed diffusion or company bargaining power.
