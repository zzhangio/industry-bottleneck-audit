# AI short-drama public visual v2 brief

## Purpose

Produce two views from the same frozen judgment:

1. a full interactive HTML for audit and scenario inspection;
2. a Markdown-native cover graphic that remains legible inside a GitHub README.

This is a judgment demo, not a live dashboard.

## Memory sentence

AI widens ordinary content production, but qualified monetizable short drama still narrows at controllable delivery, rights and content acceptance, platform distribution, and ownership of audience feedback.

## Frozen analytical boundary

- Qualified output `Y`: a repeatable portfolio of AI-assisted short dramas that passes rights and content review and reaches platform retention or monetization thresholds.
- Scope: China mobile micro-drama and AI comic-drama workflows using advertising, in-app payment, licensing, or platform revenue share.
- Evidence cutoff: 2026-09-29.
- Current class: production relaxation plus bottleneck migration, with a platform-centered feedback cone and smaller clusters around proven IP, workflow, and distribution.
- The visual must not imply that node importance automatically produces company profit or owner capture.

## Primary decision path

Keep the first view to these functions:

```text
story / asset intent
-> scalable AI generation [widened]
-> controllable continuity and human acceptance [local constraint]
-> rights, content review and AI labeling [hard gate]
-> platform recommendation and monetization [main commercial waist]
-> audience result
-> portable or captive feedback for the next title [learning leverage]
```

The strongest counterforce is multi-platform distribution plus portable audience data. The largest unknown is the absence of comparable industry-wide medians for AI-title profitability, exposure, and bargaining outcomes.

## Visual hierarchy

- First glance: production widened; the narrowest commercial passage moved downstream.
- Second glance: regulatory acceptance is a gate but not private rent; platform control combines entry, ranking, monetization, removal, and feedback.
- Drill-down: past baseline, conditional futures, evidence limits, substitutes, falsifiers, and company-capture caveat.
- Do not put repeated `if / if not` prose on the primary map.
- Use topology, channel width, gates, convergence, and a visible feedback return. Avoid a card grid as the main picture.

## README graphic

- Target a wide 1.8-2.0:1 composition suitable for GitHub Markdown.
- Use a light background that blends with GitHub README pages.
- Use 5-7 large labels; no tiny metadata, buttons, navigation, source ledger, or long explanation.
- It should work as a static PNG at roughly 900-1100 px rendered width.
- One short legend may distinguish widened input, hard gate, commercial waist, and feedback leverage.
- The image links to the interactive HTML; it need not reproduce every interaction.
